# メインエージェント

ISUCON の当日、**何を回すかを決め、自分で回す**ループ。main の canonical checkout で動く agent 1 本で持つ。判断の土台は `AGENTS.md` の「考え方」。この skill は、それをどう回すかだけを書く。

## 回し方

### 最初

1. inventory・取り込み・初回反映・ベースラインのベンチを流す（`isu-kickoff`）。
2. **利用者の動きを読む。** ベンチのログを利用者ごとに時刻順に並べ、何を見て、何をして、次に何をするかを読む。読みながら、サーバーの資源・サーバーの間の回線・データの大きさと読み書きの量も測る。
3. 何がスコアを生むかを説明する（マニュアルと、読んだ動き。skill `app-profile`・`score-model`）。説明できない所は、実験で確かめる（skill `probe-experiments`）。
4. **理屈で形を決める。** 見たものから、制約に最も合う形を考え、今の形と比べる（skill `capacity-plan`）。決める合図は時刻ではなく、理屈がつながったとき。`docs/DECISIONS.md` に 3 段で書く。

### ベンチのたびに

1. 結果を読み、作戦ボード（`docs/README.md`）の数字を直して、`docs/experiments.md` に 1 行足す。
2. 狙いは消えたか。次に何が見えたか。説明できない数字は無いか。
3. 考え方に戻って次の施策を選ぶ。形を変えるべき理由が見えたら、その場で判断を出し直す。
4. 反映して、`bin/isu-bench --note "<狙い>: <変更>"` を流す（ポータルでしか流せない回は Chrome の道具で Enqueue を押し、job のページを終わりまで読む）。ベンチは最初の 1 本から自分で流す。同時に 1 本、終わるまで競技サーバーを変えない。ベンチの間は待たず、次の仕事をする。

大きな仕事は subagent に渡してもよい（skill `delegate`）。返ってきたブランチは差分を読んでから取り込む。

### 作り直すとき

- 今のバージョンでスコアを取りながら、ブランチで作る。切り替えの前に、DB の写しに旧バージョンと新版を並べて同じ要求を流し、応答を比べる。基準は仕様で、初期実装ではない。
- ベンチで落ちたら、落ちた所を直して流し直す。途中の 0 点や fail は、やめる理由にならない。
- 旧バージョンはいつでも戻せるようにしておく。凍結の前に通らなければ旧バージョンで終える。
- 詳しくは isucon-kit の `docs/tuning/16-rewrite-strategy.md`。

### 終盤（時刻は `docs/RULES.md`）

- 再起動試験: 全サーバーを同時に再起動し、手作業なしで上がり、書いたデータが残り、直後のベンチが通ること（`isu-reboot-test`、`isu-finalize`）。版が固まっていれば前倒ししてよい。
- 凍結は時間割の時刻に行い、前倒ししない。凍結のバージョンを決めた後も待たず、ブランチで差を詰め、間に合わなければ捨てる。
- 最終のスコアが最後の 1 本で決まる回は、どこで止めるかを期待値で考える（`tools/stop-rule` が使える）。
- 凍結・終了の後は、競技サーバーに反映しない。

## 読むときの知識

- スコアはぶれる。ぶれの幅より小さい差は差なし（`tools/noise`）。同じバージョンでスコアが 2 つの峰に分かれたら、スコアではなくプロファイルと区分ごとの数字で読む（skill `experiment-rules`）。
- サーバーの CPU は、ベンチ中の秒ごとの最大で見る。平均で「余っている」と読まない。
- CPU の命令に効く施策は、競技サーバーで測る。手元のマシンとは CPU の機能が違う。
- 外の資源（ベンチ・外部サービス）が壁に見えたら、その量の多くはこちらの応答が作っている。先に作っている量を数える。
- 原因が分からないときは、コードを読むだけで打ち切らない。失敗した 1 件ごとに、要求と、直前に返した応答を並べる。

## 聞かずに決める

- 人間にも依頼元にも、質問・承認の依頼・判断の依頼をしない。返事も待たない。区切りは記録に書くだけで、送らない。入力が届いたら、情報として取り込む。
- 危険のある施策（永続化を弱める設定など）も自分で決める。マニュアルの禁止・失格に当たるものは入れない。当たらないものは「pass する確率 × 点」で比べ、危険・確かめ方・撤回の条件を `docs/DECISIONS.md` に書いてから入れる（`tools/flags durability` はこの記録を確かめる）。
- マニュアルで分からない仕様は、失格・減点にならない側に倒して仮置きにし、ベンチと初期実装の振る舞いで確かめる。

## コンテキスト

- 会話のコンテキストは消えるものとして扱い、決めたことはその場で `docs/` に書く。
- 時刻は `date` で確かめて書く。残り時間も `date` から数える。
- 使用量が 60% を超えたら、ベンチの最中でない区切りで手動で compact する。残すもの（自分の役、進行中の件、次の一手、動かしている処理の ID）を指定する。凍結の前にも 1 回済ませる。Claude Code は `/compact <残すもの>`、Codex は `/compact`。
- ベンチは道具（`bin/isu-bench`・`isu-lock`）で起動し、重ねて走らせない。

## Codex で使うとき

- subagent の代わりに `codex exec` を使う（skill `delegate`）。AskUserQuestion・`bin/ask`・`herdr-ask` は使わない。
