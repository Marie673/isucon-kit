# 監査

区切り（`tools/checkpoint` の audit・review）で、メインエージェントが監査役の subagent を出して、この表と記録を突き合わせさせる。監査役は読み取りだけで、ボトルネック表・DECISIONS.md を書き換えない。返すのは「当たっている項目・根拠（ファイル:行、results の id）・メインエージェントに勧める一手」だけ。

依頼文の例:

```
監査役として、skill audit の各項目を、docs/DECISIONS.md・作戦ボード（docs/README.md）のボトルネック表・design.md の D・docs/experiments.md・results/ と突き合わせてください。
読み取りだけ。競技サーバーには触らない。20 分以内に、当たっている項目ごとに「根拠（ファイル:行・results の id）・勧める一手」を 15 行以内で返す。当たっていない項目は書かない。
```

## 方向

| # | 項目 | 当たっているしるし |
|---|---|---|
| 1 | 0 ベースの設計がない、または継ぎ足しを選んだ根拠が計算でない | `docs/design.md` の D6 が空、DECISIONS.md に、今の形のままボトルネックを取り除ける計算がない |
| 2 | 却下した案の理由が、ボトルネックを取り除けるかの計算でない | 「作り込みが大きい」「整合の危険」「メモリに乗らない」「時間が足りない」を理由にしている（作り込みは subagent で並列に、整合は通るまで直す。大きさ・時間は回避の形を挙げて突き合わせる）。却下の前提が局所の速さで書かれている |
| 2a | 撤回の条件を満たしたのに、判断を出し直していない | README.md の判断の数字の「撤回の条件」と、直近のボトルネック・CPU の内訳・スコアを突き合わせる。DECISIONS.md の撤回条件が表に写っていない |
| 3 | 判断の前提が崩れている | 残り時間・データの大きさ・スコアの式の項が、判断の時と変わった。残り時間を `date` で数えていない |
| 4 | スコアが 30 分以上更新されていない | results/ の最高のスコアの時刻 |
| 5 | 入力が有限で決まっている計算を、ベンチの中でしている | 入力が前もって分かる計算を要求ごとにしている |
| 6 | 計算を CPU の機能の合うサーバーに置いていない | `tools/cpu-features` の結果と、重い計算の置き場所 |
| 7 | こちらで選べる値の、許される範囲を確かめていない | `docs/design.md` の B5 の「選べる範囲（出典）」が空 |
| 7b | CPU の上位の処理に「前計算・結果を覚える・サーバーを移す」を当てていない | ボトルネック表に答えがない |
| 7c | スコアの式の項・取りこぼしが古い | 判断の数字の数字が直近のベンチより前のまま。どの項を何が止めているかが書かれていない。ボトルネック表の「取りこぼしの合計」が空 |
| 7d | スコアの目標や 1 本のスコアの比較で判断している | 「目標」「目安」「今の版を上回らなければ」で手を止めた・やめた行がある。狙ったボトルネックが消えたかを見ていない |

## 測り方

| # | 項目 | 当たっているしるし |
|---|---|---|
| 8 | 二峰のスコアを、変更の効果と読んでいる | 同じ版で 1 割以上離れた 2 本があるのに、1〜2 本の差で採否を決めた行がある |
| 9 | 効き目を手元のサーバーで測って捨てた | 手元（M 系など）の計測で「差なし」とした CPU の命令に効く手 |
| 10 | サーバーの CPU を平均で見ている | ベンチ中の秒ごとの最大を見ていない |

## 流れ

| # | 項目 | 当たっているしるし |
|---|---|---|
| 11 | 待機している・返事を待っている | 作戦ボードに「待つ」「止める」、ベンチの合間に何もしていない時間 |
| 12 | 人間・依頼元に質問・承認を求めた | `herdr-ask`・`bin/ask` の送信、「承認を」「判断を」の文 |
| 13 | 凍結を前倒ししている | 凍結の時刻が時間割より早い |
| 14 | 最終ベンチを本数で決めている | `tools/stop-rule/stop-rule` を使っていない（最終のスコアが最後の 1 本で決まる回） |
| 15 | subagent を使わず、大きな仕事を直列に抱えている | コンテキストの使用量が 60% を超え、ボトルネック表の並列にできる行が残っている |
