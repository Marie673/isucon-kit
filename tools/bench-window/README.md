# bench-window

ベンチの「窓」だけを切り出して、nginx のアクセスログを集計する道具。

## なぜ要るか

詰まりがベンチの最後の数十秒（利用者が一斉に動く山）にしか出ないことがある。
走行全体の平均で見ていると、ボトルネックが見えない。

この道具は、見る時間帯（窓）を先に決める。窓の中だけで、次の 3 つを出す。

1. 秒単位のタイムライン（台 × 秒の件数・p50・p99・5xx・499。CPU も並べられる）
2. エンドポイント別の件数・合計時間・p99
3. 窓の中と窓の外の比較（同じエンドポイントの p99 が何倍か）

読み取りだけ。ログを読んで標準出力に Markdown を書く。サーバーには接続しない。
標準ライブラリだけの Python。`uv` で動く（`pip` は使わない）。

## 使い方

```sh
# ベンチの受付開始が 10:03:20。最後の 30 秒を見る
bench-window host1=host1/access.log host2=host2/access.log \
  --anchor 10:03:20 --from +30s --to +60s --group alp-groups.txt

# 受付開始の時刻が分からないときは、ログの最後から
bench-window host1/access.log host2/access.log --last 30s

# CPU も同じ秒に並べる
bench-window host1=a.log host2=e.log --last 30s \
  --cpu host1=host1/mpstat.txt --cpu host2=host2/cpu.csv
```

### 入力

- アクセスログは LTSV と JSON Lines の両方（1 行 1 リクエスト）。形は 1 行ごとに自動で判別する。`.gz` と `-`（標準入力）も読める。
- キーの別名を吸収する。左ほど優先。

  | 中身 | 読むキー |
  | --- | --- |
  | 時刻 | `msec` `time_iso8601` `time` `ts` `timestamp` `@timestamp` `time_local`（ISO 8601・nginx の time_local・epoch 秒/ミリ秒） |
  | 処理時間（秒） | `reqtime` `request_time` `req_time` `rt` `response_time` `duration` |
  | URI | `uri` `request_uri` `path` `url` `request_path`（クエリは落とす） |
  | メソッド | `method` `request_method` `verb`（無ければ `request` の `"GET /x HTTP/1.1"` から） |
  | ステータス | `status` `status_code` `code` |

- 台の名前は、`名前=パス` か `--host-label`（LOG と同じ順に繰り返す）で付ける。付けなければファイル名、同じ名前が重なればディレクトリ名。
  ログの中のキーを台の名前にしたいときは `--host-key KEY`。
  LTSV の `host:` は普通は `$remote_addr` なので、台の名前には使わない。
- 時刻にタイムゾーンが無いログは `--tz`（既定 `+09:00`）で読む。表示も `--tz`。

### 窓の決め方

| 指定 | 意味 |
| --- | --- |
| `--anchor T` | 基準の時刻（受付開始など）。`10:03:20`、ISO 8601、epoch。 |
| `--from X` / `--to X` | 窓の始まりと終わり（終わりは含まない）。`-5s` `+30s` `+1m` のような anchor からの相対か、絶対の時刻。既定は anchor（無ければログの先頭）からログの末尾まで。 |
| `--last 30s` | ログの最後の 30 秒（整数秒に揃える）。`--from/--to` とは併用できない。 |

窓の外は「ログのうち窓に入らなかった行すべて」。比較の基準にするので、
走行の前後だけを集めたログを渡す（前の走行のログが混ざると基準がずれる）。

### そのほかの引数

- `--group FILE`: URI をまとめる正規表現のファイル。1 行 1 つ、`#` から行末はコメント。alp の `-m` に渡すもの（`alp-groups.txt`）と同じ形。先に合った行が勝つ。表には正規表現がそのまま出る。
- `--cpu FILE`（繰り返し可）: CPU の時系列。`mpstat` の出力（`%idle` から 100 - idle を出す。`all` 行だけ）、`pidstat` の出力（`%CPU` を秒ごとに合計し、バナーの `(4 CPU)` で割って全コア平均 % に揃える。`--cpu-cores N` で上書き）、`ts,host,cpu` の CSV。12 時間表記（AM/PM）も読める。台の名前は `名前=パス`、無ければバナーのホスト名、CSV の `host` 列。ログの台の名前と同じ文字列にすると同じ列に並ぶ。
- `--timeline wide|long|none`: wide は 1 秒 1 行で台を横に並べる。long は台 × 秒の縦長（列が増える台数が多いときに）。
- `--bucket SEC`: タイムラインの刻み（既定 1 秒）。
- `--top N`、`--min-count N`（比較に使う最小の件数。既定 5）、`--ratio-warn X`（倍率がこれ以上なら太字。既定 2）。

エンドポイント別（窓の中）と、窓の中と外の比較:

```markdown
## エンドポイント別（窓の中、合計時間の多い順の上位 5）

| メソッド | エンドポイント | 件数 | 合計 s | 平均 | p99 | 最大 | 5xx | 499 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| GET | `^/api/lists/[0-9]+$` | 259 | 29.73 | 115ms | 344ms | 795ms | 3 | 1 |
| POST | `/api/items` | 43 | 6.36 | 148ms | 381ms | 381ms | 0 | 0 |
| POST | `^/api/items/[0-9]+/notes$` | 35 | 1.80 | 51ms | 111ms | 111ms | 0 | 0 |
| GET | `^/api/items/[0-9]+$` | 191 | 1.76 | 9.2ms | 24ms | 27ms | 0 | 0 |
| GET | `^/api/files/[0-9]+$` | 96 | 0.48 | 5.0ms | 26ms | 26ms | 0 | 0 |
|  | **全体** | 624 | 40.13 | 64ms | 299ms | 795ms | 3 | 1 |

## 窓の中と外の比較（p99）

倍率 = 窓の中の p99 ÷ 窓の外の p99。どちらも 5 件以上のものだけ。2 倍以上は太字。req/s は全台合計（窓の外は 30 秒で割る）。

| メソッド | エンドポイント | 倍率 | p99 中 | p99 外 | 件数 中 | 件数 外 | req/s 中 | req/s 外 |
| --- | --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| GET | `^/api/lists/[0-9]+$` | **8.8x** | 344ms | 39ms | 259 | 105 | 8.6 | 3.5 |
| POST | `/api/items` | **4.9x** | 381ms | 78ms | 43 | 26 | 1.4 | 0.9 |
| POST | `^/api/items/[0-9]+/notes$` | **2.7x** | 111ms | 41ms | 35 | 16 | 1.2 | 0.5 |
| GET | `^/api/files/[0-9]+$` | 1.9x | 26ms | 14ms | 96 | 40 | 3.2 | 1.3 |
| GET | `^/api/items/[0-9]+$` | 1.7x | 24ms | 14ms | 191 | 85 | 6.4 | 2.8 |
|  | **全体** | **6.4x** | 299ms | 47ms | 624 | 272 | 20.8 | 9.1 |
```

読み方: 負荷が 2.4 倍（req/s 9.1 → 20.8）になっただけで、`/api/lists/:id` の p99 は 8.8 倍になっている。
負荷に比例しない伸びなので、ここがボトルネック。平均の全体では埋もれる。

## 注意

- p99 は nearest-rank 法。1 秒の中の件数が少ないと p99 はほぼ最大値になる。
- `5xx` は 500〜599、`499` は nginx のクライアント切断。
- 窓の外が空（ログが窓の中だけ）のときは、比較の節は出ない。
- ログの時刻は nginx が書いた時刻（リクエストの完了時）。窓の端のリクエストは、始まりが窓の外のこともある。
